# 구현 검증 기록

실행일: 2026-10-27 (Asia/Seoul).

## 실제 환경

- Windows x64, 프로젝트 내부 임시 Python 3.13.9.
- Django 5.2.18, PostgreSQL 17.11, psycopg 3.3.6, WhiteNoise 6.12.0.
- 로컬 DB 서버: 127.0.0.1:55432. 외부 운영 DB에 접근하지 않았습니다.
- 임시 런타임/DB/로그는 .runtime 아래에 격리하며 배포 대상에서 제외합니다.
- 검증 후 임시 PostgreSQL 프로세스는 정상 종료했습니다. 현재 앱/DB 서버를 상시 실행 중인 상태는 아닙니다.

## 결과

### 기존 사이트와 경로 분리 검증

- `APP_URL_PREFIX=/note-demo` 선택적 설정 추가. 로컬 기본 경로는 유지합니다.
- 자동 테스트 43개 통과: 기존 38개에 접두사 링크/리다이렉트, 쿠키 이름·경로, 기존 사이트로의 로그인 이동 방지, 게시글 링크/저장 이동, WSGI의 경로 전달 형식 검증 5개 추가.
- 운영 WSGI는 루트 배포와 경로 배포를 별도 프로세스에서 점검합니다. 실제 alwaysdata의 새 Web 사이트 등록과 주소 라우팅은 사용자가 진행할 후속 검증입니다.
- 경로 배포에서는 HSTS를 끄므로 배포 점검에 W004 경고가 나타납니다. 같은 호스트의 기존 사이트에 HSTS 정책을 추가하지 않기 위한 선택입니다.

### 로그인 우선 진입 변경 후 재검증

- 사용자 요청에 따라 홈페이지/비로그인 게시판 접근은 로그인으로 안내하고, 로그인 아래 회원가입 링크를 배치했습니다.
- 자동 테스트 **38개 통과**, `makemigrations --check --dry-run` 변경 없음. 로그인 진입·가입 링크 위치·로그인 후 원래 글 이동·로그아웃 후 접근 차단·인증된 회원의 진입 흐름을 추가 검증했습니다.
- 사용자 서버와 분리한 8001번 임시 서버에서 브라우저로 첫 진입 로그인 화면과 회원가입 링크 이동을 확인했습니다. [로그인 화면 캡처](login-preview.png).
- 이번 변경은 `.env`/DB/패키지 수정이나 추가 마이그레이션이 필요 없습니다. 기존 8000번 개발 서버는 재시작해야 변경된 Python 코드가 반영됩니다.

### 최초 구현 검증 기록

| 항목 | 결과 |
| --- | --- |
| 빈 PostgreSQL DB에 전체 migrate | 성공 |
| manage.py check | 문제 없음 |
| collectstatic --noinput | 성공, CSS 수집 및 해시/압축 생성 |
| manage.py test | 32개 통과, 실패/오류 없음 |
| makemigrations --check --dry-run | 변경 사항 없음 |
| 운영 설정 check --deploy | 오류 없음, 의도한 HSTS 경고 W005/W021 2개 |
| 운영 WSGI 직접 요청 | HTTPS 모의 목록 200, HTTP→HTTPS 301, 해시 CSS 200, 무토큰 POST 403, 없는 글 404 |
| 실제 seed 로더 반복 실행 | 첫 실행 2개, 두번째 0개 추가 |
| pg_dump → 별도 새 DB pg_restore | 성공, 금칙어 2개 복원 확인 |

자동 테스트는 이메일 정규화/중복/해시, 로그인·로그아웃 세션 무효화, Mock, 게시글 0/10/11개와 고정 정렬, 잘못된 페이지, 작성자 권한, 편집 원문 no-store, 댓글 0/20/21개, 키워드 변경의 소급 표시, Unicode 정규화·겹침·오탐, 관리자 권한/상한, seed 중복/실패 원자성, XSS/CSRF, ORM 및 직접 SQL 삭제 관계를 포함합니다.

첫 테스트 실행에서 collectstatic 이전의 manifest 누락을 확인했고 정적 파일 수집 후 재검증했습니다. 500 오류 화면은 정적 파일에 의존하지 않도록 수정했습니다. 과도하게 긴 page 숫자도 400으로 처리합니다.

## 확인하지 않은 항목

- alwaysdata 실제 계정의 설치·사이트 등록·인증서·외부 접속·자원 한도/성능.
- 전체 화면의 모바일 레이아웃과 전체 브라우저 기능 흐름. 로그인/회원가입 진입은 후속 브라우저 검증을 완료했으며 나머지 흐름은 자동 테스트와 WSGI 응답으로 검증했습니다.
- 대규모 동시 접속이나 모든 금칙어 우회 표현 탐지.

HSTS는 해당 호스트에만 1시간 적용하며 하위 도메인 전체 적용과 preload는 의도적으로 껐습니다. 공유 계정의 도메인 통제 범위를 넘어 설정하지 않기 위한 선택이며 경고를 숨기지 않습니다.
