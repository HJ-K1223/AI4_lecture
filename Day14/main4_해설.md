# main4.py 코드 해설

## 목적

Redis에 **세션별 대화 이력을 저장하고, 이전 대화를 응답 생성 함수에 전달하는 과정**을 실습한다. 실제 LLM API는 호출하지 않고, 규칙 기반 모의 응답으로 문맥 재사용을 확인한다.

## 저장 구조

| 구분 | Redis 키 | 자료형과 값 | 만료 정책 |
|---|---|---|---|
| 세션 | `lesson04:session:{세션 ID}` | String: `demo-a` 또는 `demo-b` | 생성 후 300초. 대화해도 연장되지 않는다. |
| 대화 이력 | `lesson04:history:{세션 ID}` | List: 각 메시지를 JSON 문자열로 저장 | 마지막 메시지 저장 후 300초. 저장할 때 갱신된다. |

메시지는 `{"role": "user", "content": "안녕"}`처럼 역할과 내용을 가진다. 사용자 메시지와 모의 응답을 순서대로 저장하며, 저장 후 최근 **6개 메시지(3턴)**만 남긴다.

## 주요 함수

### `read_history(client, history_key)`

1. `LRANGE`로 대화 리스트 전체를 읽는다.
2. `json.loads()`로 각 JSON 문자열을 Python 딕셔너리로 바꾼다.
3. `role`이 `user` 또는 `assistant`인지, `content`가 문자열인지 검사한다.
4. 검증된 메시지 목록을 반환한다. 잘못된 JSON이나 형식은 오류로 처리한다.

### `make_demo_reply(messages, text)`

입력이 정확히 `내 이름이 뭐야?`이면 이전 메시지를 최신순으로 살펴본다. 사용자 메시지 중 `내 이름은 `으로 시작하는 내용을 찾아 이름을 응답한다. 없으면 이름을 찾지 못했다고 답한다. 그 외에는 `모의 응답: 입력 내용`을 반환한다.

### `main()`

명령줄 입력과 Redis 연결을 처리하고, 명령에 따라 세션과 대화 이력을 관리한다. 현재 작업 폴더의 `.env`에서 서버 주소와 포트를 읽고 검증한다. 기존 환경변수가 우선한다. Redis 응답은 문자열로 받으며, 연결 및 소켓 작업 제한 시간은 각각 2초다.

## 명령별 동작

| 명령 | 동작 |
|---|---|
| `create` | `secrets.token_urlsafe(32)`로 세션 ID를 만들고 사용자 ID를 300초 동안 저장한다. |
| `chat` | 유효한 세션인지 확인한 뒤 이전 이력으로 응답을 만들고 새 대화를 저장한다. |
| `history` | 유효한 세션의 대화 이력과 이력 키의 TTL을 출력한다. |
| `clear` | 유효한 세션의 대화 이력만 삭제하고 세션은 유지한다. |
| `logout` | 유효한 세션의 세션 키와 대화 이력 키를 함께 삭제한다. |

`create` 이외의 모든 명령은 먼저 세션을 조회한다. 세션이 없거나 만료되었으면 작업을 거절한다. `chat`에는 공백이 아닌 메시지가 필요하며, 다른 명령에는 메시지를 입력할 수 없다.

## 대화 저장 흐름

1. `read_history()`로 이전 메시지를 읽는다.
2. `make_demo_reply()`에 이전 메시지와 현재 입력을 전달한다.
3. `json.dumps(..., ensure_ascii=False)`로 사용자 메시지와 응답을 JSON 문자열로 바꾼다. 한글은 문자 그대로 저장한다.
4. `RPUSH` 한 번으로 사용자 메시지, 응답 순서대로 두 값을 추가한다.
5. `LTRIM`으로 뒤에서 6개 메시지만 남긴다.
6. `EXPIRE`로 이력 키의 만료 시간을 300초로 갱신한다.

## 실행 예시

`C:\AI4\Day14` 폴더에서 실행한다. Python 환경에는 `redis`, `python-dotenv` 패키지가 필요하다. `.env` 설정 예시는 다음과 같다.

```dotenv
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
```

```powershell
python main4.py create demo-a
python main4.py chat <발급받은_세션_ID> "내 이름은 민수"
python main4.py chat <발급받은_세션_ID> "내 이름이 뭐야?"
python main4.py history <발급받은_세션_ID>
python main4.py clear <발급받은_세션_ID>
python main4.py logout <발급받은_세션_ID>
```

`<발급받은_세션_ID>`는 꺾쇠까지 포함해 실제 출력된 `sid_...` 값으로 바꾼다. 두 번째 대화의 모의 응답은 `기록에서 찾은 이름: 민수`가 된다.

## 알아둘 점

- 답변 캐시를 검색해 재사용하는 구현이 아니라, 저장한 대화 이력을 읽어 응답 함수에 전달하는 구현이다.
- 세션 만료와 이력 만료는 독립적이다. 세션이 만료되면 이력이 남아 있어도 이 코드에서는 접근할 수 없다.
- 이름을 말한 메시지가 최근 6개에서 빠지면 이후 응답에서는 그 이름을 기억하지 못한다.
- 저장은 `RPUSH`, `LTRIM`, `EXPIRE`라는 별도 명령으로 처리한다. 전체 대화 처리 과정이 하나의 원자적 작업은 아니므로 동시 요청이나 중간 실패에 대한 처리는 별도로 필요하다.
- `main3.py`와 키 접두사가 달라 세션을 공유하지 않는다. `main4.py create`로 새 세션을 만들어야 한다.
- 입력·설정 오류와 Redis 오류를 구분해 출력하며, 실제 비밀번호 인증은 구현하지 않는다.
